# 与原 App 的对应关系和后续接入

## 本版已经实现

本版实现原 App 核心流程的一个可运行子集：机械参数 → 施工模式 → 设计参数 → 输入回放 → 姿态与设计高差 → 保存记录。

数据建模参考已恢复的 `TrenchingRecord`、`WorkModeEnum` 和演示数据结构；界面、存储代码与平面计算为本轮重新实现。这里没有宣称与原版 UI、全部业务分支和数值结果一致。

## 原版计算链

此前恢复的关键链路是 `jc.e` → `t6.d.run(case 8)` → `wajibaoModule.WajiInner_calculate` → `libbcCore`。

平面演示模式用 `ReplaySource` → `DemoPoseSolver` → `Guidance` 跑通流程。原版模式另接 `OriginalFrame` → `OriginalSession` → 原 JNI，但当前在授权检查处停止。`PoseSolver` 是当前演示边界；接入真实核心前需要扩展输入对象，承载完整 GNSS/IMU、安装模式、标定和附件参数，不能直接把三个平面角当作原 JNI 全量参数。

## 首次人工验收

1. 安装 debug APK，确认与原 App 同时存在。
2. 输入机械参数，分别进入找平和挖沟；无效尺寸应被拦截。
3. 播放后观察帧序号和高程变化，暂停、逐帧、重置均应可用。
4. 调节姿态及横向偏移，观察高差方向与沟底/边坡目标高程。
5. 两种模式各保存一个施工点，关闭重开后记录仍存在；导出 CSV 并检查输入参数和高差。
6. 旋转屏幕、进入后台再返回，确认回放没有在后台继续推进。

自动验证由 `ConstructionTest` 和 `MainActivityFlowTest` 覆盖数学边界、两种模式、记录、回放暂停及旋转恢复。Robolectric 是 JVM Android 模拟环境，不等于真机验证。
